# 在线账密保险箱 Docker 生产部署计划 v1.0

> 状态：部署方案已确认，尚未执行服务器变更。
>
> 目标服务器：单台 OpenCloudOS 9.4 主机；已确认具备 Docker 29.4 与 Docker Compose 5.1。

## 1. 部署目标与边界

本次采用单机 Docker Compose 部署，交付前端单页应用、Spring Boot 后端和 MySQL 8.4。公网只开放 HTTPS 入口；后端、数据库与 Actuator 不直接暴露到主机端口。

本计划不把本机开发配置、真实数据库口令、加密密钥或管理员初始口令提交进 Git，也不在本计划中记录这些值。

## 2. 目标拓扑

```mermaid
flowchart LR
  U[浏览器] -->|HTTPS 443| C[Caddy 反向代理]
  U -->|HTTP 80，仅跳转 HTTPS| C
  C -->|静态页面| F[前端 Nginx 容器]
  C -->|/api/*| B[Spring Boot 后端]
  B -->|私有网络| M[(MySQL 8.4)]
  B -->|容器内健康检查| H[/actuator/health]
```

| 服务 | 镜像职责 | 主机端口 | 数据持久化 | 网络边界 |
| --- | --- | --- | --- | --- |
| Caddy | TLS 证书、HTTPS 跳转、路由 | `80`、`443` | Caddy 证书数据卷 | 公网入口 |
| 前端 | 构建后的 Vue 静态文件 | 不映射 | 无 | 仅供 Caddy 访问 |
| 后端 | Spring Boot API、Flyway | 不映射 | 无状态 | 仅供 Caddy、MySQL 访问 |
| MySQL 8.4 | 业务数据、会话、Flyway 历史 | 不映射 | `mysql-data` 数据卷 | 仅供后端访问 |

前端与 API 保持同源，由 Caddy 将 `/api/*` 反向代理到后端，因此现有 Session Cookie 与 CSRF 模型不需要跨域放行。

## 3. 上线前必须完成的安全整改

以下项目是正式暴露到公网前的阻断项，不完成不得启动生产服务：

1. **生产配置隔离**：新增 `prod` Profile，数据库地址、账号、口令和邀请码加密密钥全部只从服务器受保护的环境文件注入。
2. **移除不安全默认值**：生产环境不得使用当前应用配置中的邀请码加密密钥回退值；生产启动时缺少 `INVITATION_ENCRYPTION_KEY` 必须失败。
3. **管理员初始化改造**：当前迁移中存在开发用种子管理员及其口令哈希更新逻辑。生产库不得自动创建或重置可预测管理员；改为一次性、人工受保护的管理员初始化流程，并在首次登录后强制修改。
4. **Flyway 生产策略**：生产禁用启动时自动 `repair`，只允许在已备份、人工确认的故障处理流程中执行。迁移执行前必须完成数据库备份。
5. **会话安全**：生产固定 `SESSION_COOKIE_SECURE=true`；Caddy 终止 TLS 后仍由应用只签发 `HttpOnly`、`Secure`、`SameSite=Lax` Cookie。
6. **运维访问收紧**：创建专用 `deploy` 用户并使用 SSH 密钥；验证完成后限制 root 远程密码登录。云安全组仅对运维来源开放 `22`，仅对公网开放 `80/443`。
7. **密钥与备份**：生成独立的高熵数据库口令和 32 字节 Base64 邀请码加密密钥；将加密后的数据库备份保存到主机外的对象存储，并完成一次恢复演练。

## 4. 仓库改造清单

实施阶段新增或调整以下文件；真实 `.env` 文件只在服务器创建并加入 Git 忽略。

| 文件 | 用途 |
| --- | --- |
| `backend/Dockerfile` | 多阶段构建 Maven 包并使用 Java 25 JRE 运行 |
| `frontend/Dockerfile` | 构建 Vue 静态资源并交由 Nginx 提供 |
| `deploy/compose.yml` | Caddy、前端、后端、MySQL 的编排、网络、数据卷和健康检查 |
| `deploy/Caddyfile` | 域名 HTTPS、`/api/*` 代理与静态站点路由 |
| `deploy/.env.production.example` | 仅变量名和非敏感示例，不含真实值 |
| `backend/src/main/resources/application-prod.yml` | 生产 Profile，关闭开发回退配置与自动 Flyway repair |
| `docs/运维与备份手册.md` | 首次部署、升级、备份、恢复与故障处理命令 |

镜像采用明确版本或不可变摘要，不使用 `latest`。首次部署可在服务器从受保护的 Git 标签构建；稳定后再接入 CI 构建镜像并推送到镜像仓库。

## 5. 服务器准备步骤

1. 申请并解析生产域名到服务器公网 IP；Caddy 自动签发证书需要该域名的 `80/443` 可达。
2. 在云安全组开放 TCP `80/443`，将 TCP `22` 限制为维护 IP 段；服务器本机 firewalld 当前未启用，仍需以云安全组作为第一道公网边界。
3. 创建部署目录 `/opt/online-safe`，仅授予 `deploy` 用户写入权限；创建 `mysql-data`、`caddy-data`、`backups` 目录。
4. 在服务器创建权限为 `600` 的 `deploy/.env.production`，填入域名、数据库名称、数据库专用账号口令、邀请码加密密钥和生产 Cookie 设置。
5. 从已审批的 Git 发布标签检出源码，核对提交号与本地构建测试结果一致。

## 6. 首次部署流程

1. 本地执行后端测试和前端生产构建，且检查 Git 暂存内容不含本地配置或密钥。
2. 构建镜像并执行依赖漏洞扫描；记录镜像摘要。
3. 启动 MySQL，等待健康检查通过；数据库不映射宿主机端口。
4. 对空数据库执行受控 Flyway 迁移；在此之前再次确认第 3 节的管理员初始化整改已完成。
5. 启动后端，确认容器内 `/actuator/health` 返回 `UP`。
6. 启动前端与 Caddy，验证 HTTP 自动跳转 HTTPS、登录、注册、管理员入口、会话 Cookie 和 CSRF 请求。
7. 从外网验证仅 `80/443/22` 可达；确认 `8080`、`3306` 与 Actuator 没有对公网监听。
8. 创建首次加密备份，并用独立临时环境完成恢复验证后，记录部署版本、迁移版本和备份标识。

## 7. 验收清单

- [ ] 域名证书有效，HTTP 自动跳转 HTTPS。
- [ ] `docker compose ps` 中四个服务均健康或运行正常。
- [ ] 前端刷新任意路由不返回 404。
- [ ] 个人用户与管理员登录、退出、CSRF 校验正常。
- [ ] 后端和数据库端口未映射到宿主机。
- [ ] 生产环境无开发默认管理员、默认加密密钥或本地开发数据库配置。
- [ ] Flyway 历史与应用版本匹配，且没有失败迁移记录。
- [ ] 已完成备份与恢复演练。

## 8. 升级、回滚与备份

### 升级

每次升级使用新的 Git 标签或镜像摘要，依次执行：备份数据库 → 核对迁移说明 → 拉取/构建镜像 → `docker compose up -d` → 健康检查 → 业务冒烟测试。数据库迁移为前向兼容时才允许滚动升级。

### 回滚

应用代码可回滚到上一镜像摘要；如果本次已执行不可逆数据库迁移，不得仅回滚应用。必须先评估迁移兼容性，否则使用已验证的备份恢复到隔离环境后再决定恢复策略。

### 备份

每日执行 MySQL 逻辑备份并加密上传至主机外存储；保留周期建议至少为 7 个日备、4 个周备和 3 个月备。每月至少进行一次恢复演练，验证可启动服务、可登录且数据完整。

## 9. 实施顺序与责任边界

| 阶段 | 产出 | 是否会改动服务器 |
| --- | --- | --- |
| A. 仓库容器化 | Dockerfile、Compose、Caddy、生产配置与文档 | 否 |
| B. 本地验收 | 镜像构建、容器健康检查、端到端冒烟 | 否 |
| C. 服务器准备 | 部署用户、目录、云安全组、域名和密钥文件 | 是，需确认 |
| D. 首次上线 | 构建、迁移、启动、HTTPS 与功能验收 | 是，需确认 |
| E. 运维固化 | 备份、监控、镜像发布与恢复演练 | 是，需确认 |

建议下一步先实施阶段 A：在仓库内补齐生产容器化文件和生产安全配置，通过本地 Compose 验收后，再由你确认是否执行阶段 C、D 的服务器变更。

# Online Safe 设计规范

## 1. 文档目的

本文档定义 Online Safe 第一版的界面与交互标准，适用于个人登录、注册、管理员入口、管理后台和保险箱页面。目标是在不削弱安全感的前提下，降低填写成本、让状态更易理解，并保证桌面端与移动端都能顺畅使用。管理后台筛选条（搜索、下拉、查询）默认采用紧凑控件，避免工具区占据过大纵向空间。

本文档优先级低于产品需求文档、接口安全约束和项目级 [`AGENTS.md`](../AGENTS.md)；页面文案、提示信息和注释均使用中文。

## 2. 当前问题诊断

基于现有登录页和注册页的实际检查，当前版本存在以下体验问题：

| 问题 | 对用户的影响 | 设计处理方式 |
| --- | --- | --- |
| 后端连接提示位于页面最顶端 | 首屏主任务被大面积告警打断，页面整体向下位移 | 降级为表单区域内的紧凑状态提示，并提供明确的重试动作 |
| 桌面端左右两栏视觉权重接近 | 安全介绍与登录表单争夺注意力，用户难以立刻找到下一步 | 左侧仅承担品牌与安全承诺；右侧表单成为唯一视觉焦点 |
| 注册项在单页连续堆叠 | 用户看不到完成进度，首次提交才知道格式问题 | 使用两步注册，并在字段失焦时给出就近、可执行的提示 |
| 说明文字与安全提示较多 | 信息密度过高，容易被忽略 | 每个界面只保留一条与当前动作直接有关的安全说明 |
| 管理员入口的状态不够明确 | 用户可能误以为管理员登录已经可用 | 显式展示“管理员登录暂未开放”，避免伪表单或不可用操作 |
| 小屏幕仅隐藏左侧内容 | 页面在移动端缺少身份与安全上下文 | 在表单标题前提供精简的安全标识与一句说明，保留必要的上下文 |

## 3. 设计目标与原则

### 3.1 产品气质

Online Safe 是保存敏感账户信息的工具。界面应传达“可靠、克制、清晰”，而不是用深色、警告色或复杂动效制造紧张感。

### 3.2 五项原则

1. **主任务优先**：首屏只让用户清楚看到一个主要动作，例如“登录”或“继续注册”。
2. **安全可理解**：用短句说明安全边界，不堆叠抽象术语，不暗示尚未实现的能力。
3. **反馈就近出现**：字段问题在字段下方说明；提交问题在提交按钮上方说明；不使用只有颜色的反馈。
4. **渐进呈现**：注册、保险箱录入等较长流程按用户当前所需拆分，不一次要求理解所有内容。
5. **移动端完整可用**：手机端不是桌面端的裁剪版，首屏必须完整展示当前任务、关键输入和主按钮。

## 4. 视觉系统

### 4.1 色彩

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 页面背景 | `#F7F9FC` | 微冷白背景，降低大面积纯白带来的生硬感 |
| 表面与表单卡片 | `#FFFFFF` | 卡片不使用粗重边框 |
| 主色 | `#155EEF` | 主按钮、焦点环和重要链接 |
| 深色文字 | `#101828` | 标题和关键内容 |
| 次级文字 | `#475467` | 说明、辅助信息 |
| 边框 | `#D0D5DD` | 输入框静态边框 |
| 成功 | `#027A48` | 成功状态，不用于可点击元素 |
| 警告 | `#B54708` | 服务连接或需要用户留意的状态 |
| 错误 | `#B42318` | 校验与提交失败 |
| 安全侧栏 | `#172B4D` | 仅用于宽屏身份页左侧背景 |

错误、警告和成功状态必须同时包含图标、文字和颜色。

### 4.2 字体与层级

- 字体：`Inter`、`PingFang SC`、`Microsoft YaHei`、系统无衬线字体。
- 页面标题：28px / 36px / 700。
- 表单标题：24px / 32px / 700。
- 正文：14px / 22px / 400。
- 辅助文字：12px / 18px / 400。
- 不用全大写英文作为中文界面的主要文案；敏感值展示时可在后续保险箱模块使用等宽字体。

### 4.3 间距、圆角与阴影

- 采用 4px 间距网格，常用间距为 8、12、16、24、32、48px。
- **控件高度分档**（整体偏紧凑，避免管理后台筛选条过大）：
  | 场景 | 高度 | 说明 |
  | --- | --- | --- |
  | 搜索框、下拉框、筛选条内按钮 | 36px（`density="compact"`） | 管理后台、保险箱工具栏默认 |
  | 普通操作按钮 | 40px | Vuetify 全局 `VBtn` 默认 |
  | 认证主按钮、关键提交 | 48px | `.auth-submit` 等局部样式保留触控友好高度 |
- 移动端可点击目标仍尽量接近 44px；筛选条在窄屏可垂直堆叠，不必强行拉高每个控件。
- 输入框圆角 10px，卡片圆角 16px，标签或状态圆角 999px。
- 卡片使用轻阴影 `0 12px 32px rgba(16,24,40,.08)`，避免蓝色粗左边框和重阴影同时出现。
- 键盘焦点使用 3px、低透明度的主色外圈，不能只依赖浏览器默认样式。


## 5. 页面布局

### 5.1 认证页面

| 断点 | 布局规则 |
| --- | --- |
| `>= 1280px` | 双栏布局：安全介绍区占 42%，表单区占 58%；表单最大宽度 440px。 |
| `960px - 1279px` | 安全介绍区缩至 34%，只保留标题、一句说明和两条安全能力；表单最大宽度 440px。 |
| `< 960px` | 单栏布局。顶部仅保留品牌、当前入口切换和简短安全说明；移除页脚中的非必要合规占位文字。 |
| `< 480px` | 页面内边距 20px；卡片取消悬浮感，采用无边框表面；主按钮固定在表单自然流中，避免遮挡输入项。 |

认证页面的首屏顺序固定为：品牌与入口切换、标题与当前任务说明、表单、主按钮、辅助跳转。安全承诺只能作为辅助信息，不能抢占主按钮的位置。

### 5.2 登录页

- 个人登录和管理员入口使用分段切换控件，当前项具备清晰的背景、文字和焦点状态。
- 账号输入框标签为“手机号或用户名”；密码标签右侧不展示不可点击的“暂不支持找回”，改为表单下方的简短说明。
- 登录失败提示显示在表单标题与第一个字段之间，说明下一步，例如“账号或密码不正确，请重新输入”。
- 登录按钮加载时保留“正在登录”文字并禁用重复提交；请求完成后恢复。
- “立即注册”使用普通链接样式，不与主按钮竞争。

### 5.3 注册页

注册采用两步流程，避免用户面对长表单：

1. **创建账号**：手机号、用户名、邀请码。
2. **设置密码**：登录密码、确认密码、阅读并同意条款。

页面顶部显示“步骤 1/2”与简洁进度条；返回上一步不丢失已填写内容。第二步提交成功后，展示“注册成功，正在进入保险箱”的过渡状态，再进入登录后的页面。

### 5.4 管理员入口

管理员入口在管理员认证接口实现前只展示受控的说明状态：

- 标题：“管理员入口”。
- 说明：“管理员登录正在接入中，个人用户请使用个人登录入口。”
- 主操作：“返回个人登录”。
- 不展示账号、密码输入框，也不提供看似可用但实际无效的登录按钮。

## 6. 表单与交互规范

### 6.1 校验时机

| 场景 | 行为 |
| --- | --- |
| 初次进入 | 不主动显示错误。 |
| 输入过程中 | 仅展示密码规则、用户名格式等帮助性提示；不在每次按键时打断用户。 |
| 字段失焦 | 校验该字段，错误显示在字段下方。 |
| 提交时 | 校验全部字段，自动聚焦第一个错误字段。 |
| 服务端返回字段错误 | 映射到对应字段；不能只在顶部显示笼统的“没有访问权限”。 |

### 6.2 输入辅助

- 手机号输入使用数字键盘、自动去除空格，并说明仅支持中国大陆手机号。
- 用户名旁显示“3–32 位，可使用字母、数字、下划线和连字符”。
- 密码输入实时展示规则完成情况：至少 8 位、两次输入一致；密码可见性按钮必须带可访问名称。
- 邀请码说明“由管理员或邀请渠道提供”；不在前端暴露正确邀请码。
- 条款复选框的点击目标覆盖完整文案区域，移动端易点按。

### 6.3 请求与异常状态

- 正在提交时禁用主按钮和重复跳转；按钮文案明确变化。
- 网络不可用时，在表单内显示紧凑提示，并提供“重新连接”操作；不使用覆盖整个页面的告警条。
- 成功、失败和加载状态不得改变页面主区域宽度或导致内容明显跳动。

## 7. 组件约束

| 场景 | Vuetify 组件 | 规范 |
| --- | --- | --- |
| 主操作（认证） | `v-btn` | `color="primary"`、全宽、**48px** 高、加载文案明确。 |
| 工具栏操作 | `v-btn` | 默认 **40px**；筛选条旁「查询/刷新」可用 **36px**。 |
| 文本输入 / 搜索 | `v-text-field` | `outlined` + **`density="compact"`**（全局默认）、清晰标签、就近错误文本。 |
| 下拉选择 | `v-select` | 与搜索框同密度、同圆角；筛选条内宽度宜短（约 150–180px）。 |
| 入口切换 | `v-btn-toggle` 或语义化分段控件 | 只用于互斥入口，并支持键盘操作。 |
| 状态提示 | `v-alert` | `density="compact"`；仅在对应任务区域出现。 |
| 统计卡片 | `.admin-stat-card` | 紧凑布局（约 12–14px 内边距）；图标 34px 靠右；标签+数值左列紧排；语义色区分主色/绿/橙/红/蓝。 |
| 多步骤注册 | 轻量自定义步骤栏（或 `v-stepper`） | 切换不丢失表单状态，支持返回；避免 `v-window` 裁切浮动标签。 |

全局默认在 `frontend/src/plugins/vuetify.ts`：`VTextField` / `VSelect` / `VAutocomplete` / `VCombobox` 使用 `density: 'compact'`；认证页主按钮通过样式类保持 48px。

禁止事项：

- 不使用内联 `style` 承担主布局。
- 不以“左边一条蓝线”作为卡片唯一识别方式。
- 不把尚未实现的功能展示为可操作控件。
- 不用只依赖颜色的必填、错误、成功或选中状态。

## 8. 无障碍与响应式要求

- 所有输入框都有可见标签；图标按钮包含 `aria-label`。
- Tab 键顺序与视觉顺序一致；焦点永远清晰可见。
- 文本与背景的对比度满足 WCAG AA；常规文本对比度不低于 4.5:1。
- 支持 `prefers-reduced-motion`，动效时长控制在 160–220ms，不使用闪烁和大幅位移。
- 在 390×844、768×1024、1440×900 三种视口中，首屏都必须可见标题、至少一个关键输入项和主操作。

## 9. 保险箱首页

### 9.1 页面目标

保险箱首页是用户登录后的工作台。它应优先帮助用户找到记录和新增记录，而不是展示敏感内容或复杂的统计图表。

- 首屏展示“我的保险箱”、记录数量、搜索和“新增记录”主操作。
- 支持按平台、渠道、状态和标签筛选，并按更新时间、创建时间或到期时间排序。
- 支持卡片与列表两种视图；记录仅展示名称、平台、渠道、状态、标签和更新时间。
- 账号、密码、2FA 密钥和自定义敏感字段不得在首页直接显示。
- 新用户的空保险箱应有明确的首条记录引导，不填充虚假的账号数据。

### 9.2 响应式规则

| 断点 | 布局规则 |
| --- | --- |
| `>= 960px` | 固定左侧导航、顶部状态栏和右侧工作区；筛选与视图切换位于同一工具栏。 |
| `< 960px` | 收起侧栏，顶部仅保留品牌、必要状态和用户入口；底部提供四项主导航。 |
| `< 600px` | 标题、主操作、搜索和筛选按垂直顺序排列；新增记录按钮全宽；首屏保留第一条记录或空状态引导。 |

### 9.3 交互边界

- 搜索、筛选和排序在已解密的本地记录集合中执行；在加密和记录接口接入前，首页仅提供无数据的操作外壳。
- 未实现的模板、标签、通知和记录详情入口必须给出明确的“正在开发中”反馈，不能伪装成可用功能。
- **不提供**「锁定保险箱」入口；登录成功即可使用。同一标签页刷新后从 `sessionStorage` 恢复 DEK，无需再输登录密码；关闭标签页或会话过期后重新登录即可。
- 新增记录入口在录入接口未接入前，只说明后续能力与敏感字段保护边界。
- 注册含密保步骤；登录页提供「忘记密码」（密保重置，非短信/邮箱）。

## 10. 改造顺序

1. 抽离认证页公共壳层，统一顶栏、表单容器、状态提示和移动端规则。
2. 重构登录页的层级、加载状态与连接异常提示。
3. 将注册页改为两步流程，并补齐字段失焦校验和密码规则反馈。
4. 调整管理员入口为明确的受控状态页。
5. 实现保险箱首页的导航、空状态、搜索筛选外壳和元数据展示规则。
6. 为后续记录录入、详情、模板与安全设置复用首页的颜色、间距和状态规范。

## 11. 验收清单

- 登录、注册、管理员入口在桌面与移动端都没有横向滚动、遮挡或首屏关键内容被挤出。
- 用户在提交前能理解手机号、用户名、密码和邀请码的格式要求。
- 错误信息能定位到具体字段；网络错误不会被误解为权限错误。
- 密码显示/隐藏、入口切换、步骤前进/返回和提交加载状态均可通过键盘或触控完成。
- 管理员登录未实现时，页面不会暗示可登录。
- 保险箱首页不显示任何敏感字段；空状态不会伪造用户记录。
- 保险箱首页在桌面与移动端都能看到页面标题、搜索或筛选入口，以及新增记录操作。
- 全部新增或调整的用户可见文案为中文。
